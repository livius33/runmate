<objective>
## Goal
Four test agents, each in its own git worktree, go through one area each and look for real defects, above all on
rarely used paths. Each confirmed bug gets a failing test, the smallest fix and its own commit. The commits are
reviewed and merged into the milestone branch.

| Agent | Area |
|-------|------|
| editor | Week editor, manual edits, every API that saves plan state (round trip payload → schema → store → load) |
| generator | lib/plan/generator, methodologies, athlete profile; a wide grid of inputs against the rules' invariants |
| adapter | Engine, suggestions (workshop), pause and return, feedback; whole blocks simulated week by week |
| data | Tenant isolation of every query, sources and imports, analytics, export/delete, access rules, secret scan |

## Purpose
The app goes in front of strangers. What they find first should not be a bug.
</objective>

<acceptance_criteria>

## AC-1: Findings are reproducible
```gherkin
Given a bug an agent reports as fixed
Then a test exists that failed before the fix and passes after it
```

## AC-2: Nothing else moved
```gherkin
Given the merged fixes
Then `npx tsc --noEmit` and `npm test` are green and no feature, threshold or price changed
```

## AC-3: Open points are written down
```gherkin
Given a finding that is a coaching or design question, or needs a migration
Then it is listed in the SUMMARY with the numbers, not changed
```

</acceptance_criteria>

<boundaries>
## DO NOT CHANGE
- Billing tiers, app/(dashboard)/plan/anpassen UI, onboarding UI (rebuilt in phases 9–11)
- Engine and generator thresholds (they follow methodologies/research/)
## SCOPE LIMITS
- Local Postgres only (port 5433), never the production database; no real third-party calls
</boundaries>
