<objective>
## Goal
Drive the real app in a browser as someone who has never seen it: sign up, onboarding, first plan, the overview,
every dashboard page with no data and with imported data, a kettlebell toggle and a Zone 2 switch in the week
editor, Plan anpassen (each area: preview, apply, undo), settings, export, delete account. On a phone-sized and a
desktop-sized window. Runs last, on the finished milestone branch.

## Purpose
Logic tests cannot see a page that crashes, a button that does nothing, or a layout that breaks at 390 px.
</objective>

<acceptance_criteria>

## AC-1: No dead ends
```gherkin
Given a new account without any data
When I follow the onboarding to the end and open every page in the navigation
Then no page shows an error, an endless spinner or content from another product area
```

## AC-2: Edits stick
```gherkin
Given a generated plan
When I switch a kettlebell marker on, reload the page, and switch a tempo day to Zone 2 and back
Then the page shows what I chose after each reload
```

## AC-3: Findings fixed or listed
```gherkin
Given a defect found in the walkthrough
Then it is fixed with a test where a test can catch it, or listed in the SUMMARY
```

</acceptance_criteria>

<boundaries>
## SCOPE LIMITS
- Local Postgres (port 5433), dev server on port 3100, Clerk keyless development instance with test addresses
- Paddle checkout itself is not driven (no sandbox keys); the billing states are tested at the logic level
</boundaries>
