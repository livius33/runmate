<objective>
## Goal
The onboarding that exists (consent → profile → data source or skip → race or "ohne Ziel" → plan) is walked with a
brand-new account in the browser, and everything that gets in a new runner's way is fixed: wrong or silent defaults, a
first plan that ignores what the runner told us, and pages that talk about data the runner does not have.

## Purpose
Runmate goes public. The first ten minutes decide whether a runner stays; nobody is there to explain.
</objective>

<context>
Walk-through of 2026-11-18 (new account, no data source, 30 km per week on 5 days, half marathon in 20 weeks):
- "weiß ich nicht" under HFmax and Ruhepuls: the text is inside the number field's label, so a click on it focuses the
  field and leaves the box unticked. An empty HFmax is saved as "no value" and the app runs on the example 190.
- The first plan: five runs of 5 km, longest long run of the block 10 km. Two causes: without a run the generator reads
  the longest run of the last 30 days as 0 km, and the template's long-run share (25–30 % of the week) is a rule for
  high volume – at 30–40 km per week it holds the long run at 7.5–10 km whatever the runner has done before.
- "ohne Ziel": the base block has no long run at all (25 % of 30 km is under its 8-km minimum) and its key session
  runs at 4:52/km, an example pace nobody measured.
- "Renntag" without a race: a full marathon race plan for "Kein Ziel" on 31.12.2999.
- Preview: "Renntempo /km" (empty), five hints, one of them an internal note ("VDOT-Tabellen fehlen noch").
- App: header "Noch nie synchronisiert" without any source; "Garmin" in the volume chart's legend; Settings list
  example values by field name (hrMax, pbHr, …); the runs list is an empty table; "Rennbereitschaft: Auf Kurs" with
  nothing measured.
</context>

<acceptance_criteria>
AC-1  Profile step: a click on "weiß ich nicht …" ticks the box. HFmax empty with an age → estimated from the age with
      the note; HFmax empty without an age → a German error, nothing saved.
AC-2  The profile asks for the longest run of the last 4 weeks (optional, not longer than the weekly km). Stored in the
      training profile; used only while no run is known (research note long-run.md 2.3 first).
AC-3  Goal step without runs: the longest run is shown next to the weekly km, prefilled from the profile, and goes
      into the draft as its own input. With 30 km per week, 5 days and 12 km longest run the first week has a long run
      of 12 km (6, 6, 6, 12) and the longest long run of the block is 14.5 km; the plan says that this is short for a
      half marathon.
AC-3b Low weekly volume (research note long-run.md 1.3 first): the long-run share rises from the template's value at
      64 km per week to the safety ceiling of 40 % at 32 km and below; km and minute caps, the 10 % rule and day
      limits stay. Same ramp in the base block.
AC-4  "Ohne Ziel" without runs: the base weeks have a long run that starts from the same number (30 km per week,
      12 km longest run → 12 km). Without a known threshold pace the base block has no threshold session: strides
      instead, and its rules say why (between-blocks.md 2.1).
AC-5  Preview: race pace shown; at most one hint about where the paces come from; no internal notes.
AC-6  Without a connected source the header offers "Datenquelle verbinden" (→ Einstellungen) instead of a sync that
      cannot run; volume chart says "Gelaufen"; Settings name example values in German; the runs list has an empty
      state with the way to a source; a readiness card with nothing measured says "Noch offen"; "Renntag" without a
      race says so and leads to the season.
AC-7  Walked again with a new account at 1440 px and 390 px, race path and "ohne Ziel": no console error, no
      horizontal scroll, every main page readable without data.
AC-8  `npx tsc --noEmit` and `npm test` green; new rules covered by tests.
</acceptance_criteria>
