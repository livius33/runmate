<objective>
## Goal
One function family that takes a live generated block and a change (goal time, race date, method, profile, base km)
and returns the block as it would be from next Monday, a preview against the current rest, the reasons, and the state
of the data behind each value. Applying it writes block, removed edits and a history entry; one undo restores all.

## Purpose
Today a live block is frozen: changing the goal, the date or the weekdays does nothing to it. The only way is to take
the plan offline and start over, which loses the past weeks.
</objective>

</context>

<acceptance_criteria>
AC-1  Given a live generated block and no change, when the rebuild is previewed, then weeks before next Monday are
      identical to the stored block, session by session.
AC-2  Given a change of goal time, race date, method or profile, when previewed, then the new rest comes from the
      generator with exactly that input changed, and the preview lists per week km old and new, key sessions, peak,
      longest long run, taper start and paces, plus at least one reason with a number for every difference in the totals.
AC-3  Given fewer than taper + 3 weeks from next Monday to the race, the rebuild is refused with a German sentence
      that names the week view as the way to change single days.
AC-4  Base: mean of the last 2 completed weeks of runs; with a marked pause of ≥ 4 days in the last 28 days,
      max(that, 0.7 × the level before the pause), 0.5 from 28 paused days. The source is named in the plan's rules.
AC-5  Data check: base good / thin / missing by runs in the last 4 completed weeks; goal checked / unchecked; a
      missing base requires a typed value and the answer says what is missing.
AC-6  Applying removes manual and engine edits from the cut on, stores them in the history entry, and the next plan
      load shows the new block. Undo restores block, edits and (for a date change) the Saison goal.
AC-7  Preview is free; applying needs the `rebuild` feature (402 with the upsell otherwise). Nothing is written by a
      preview.
AC-8  A property test over the generator grid: a rebuilt block passes the same invariants as a fresh draft
      (tests/plan/invariants.ts), and the past is byte-identical.
</acceptance_criteria>

<boundaries>
- Built-in example blocks and base blocks are not rebuilt (no draft behind them).
- A distance change is a new plan, not a rebuild.
- The engine's rules and the pause rules stay as they are.
- No schema migration: everything lives in settings keys.
</boundaries>
