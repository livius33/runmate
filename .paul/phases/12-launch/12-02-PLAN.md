<objective>
## Goal
Every page of Runmate follows one design system: the type scale, spacing, radius and elevation of `DESIGN.md`, with
Runmate's own colours. Pages get denser and calmer; nothing changes in what the app does.

## Purpose
Livius asked for the design to come last, picked the direction on 2026-11-21 ("choose one design approach that fits")
and then asked for this plan. Livius's notes so far: the feature card is "still too large, it has to be short and crisp",
and overview pages are a wide grid or the week strip, never a narrow column of stacked cards.

This plan replaces the earlier 12-02, which was only a checkpoint with a starting list. The redesign is not a
condition for the first deployment.
</objective>

<context>
## The reference

`DESIGN.md` at the repo root (branch `design/12-02-design-md`, commit b465301, not pushed): an unmodified third-party
analysis of Vercel's design language. It fits because Runmate already has its bones: near-white canvas, white cards,
ink primary, hairline borders. What it adds is discipline: a 4 px grid, a short type scale with a ceiling of weight
600, radii of 6 to 12 px, stacked hairline shadows, a mono face for small technical labels.

Not taken from it: its colours, accent scales and the mesh gradient. Runmate keeps ink, brand red and teal.

## Defaults taken on 2026-11-21

Livius has not answered these one by one. Until Livius says otherwise:

1. **Font:** Geist for text, Geist Mono for small technical labels (week numbers, units, eyebrows). Both come from
   `next/font/google`, so no new package; both are under the SIL Open Font License. Figures keep `tabular-nums`.
2. **Radius:** 6 px for controls (buttons, inputs, chips), 8 px for cards, 12 px for dialogs and sheets, full only
   for dots, avatars and switches.
3. **Smallest text:** 12 px. Where 12 px does not fit at 390 px, the layout changes (abbreviation, fewer columns),
   not the size. Axis labels inside charts are the one exception.
4. **Colour roles:** ink is the primary action. Brand red marks the logo, today, the key session and the focus ring.
   Teal means "on plan" or done. A new warning pair replaces the amber classes.
5. **The app stays light**; the dark set stays with the marketing pages, as now.
6. **"Feature card"** is read as the week review overlay, as in 11-02. Still to confirm.

## Order and conflicts

- One branch, one pull request: the stages build on each other and stacked pull requests are not used. The branch
  continues `design/12-02-design-md`.
- Files that open pull requests also change come last, after those are on `main`:
  `components/settings/BillingCard.tsx` and `components/legal/CancelForm.tsx` (12-05), `components/HeaderSync.tsx`
  and the new `/sign-up` page (12-04, #8).
- Code is written by Opus agents in isolated worktrees; after stage 1 the page groups of task 4 touch separate
  folders and can run in parallel. The main session reviews every diff and looks at every page in a browser.
- Pages are viewed in demo mode against the local test database (port 5433, dev server on port 3100), never
  against production data.

<acceptance_criteria>
AC-1  Tokens: one type scale (12, 14, 16, 20, 24, 32 px; 48 px on marketing pages only), one radius scale, three
      elevation levels (hairline, raised, overlay) and a warning colour pair are defined in `app/globals.css` and
      `tailwind.config.ts`, each with a comment naming the `DESIGN.md` token it comes from.
AC-2  Primitives in `components/ui/`: card, button (primary, secondary, ghost, destructive; two sizes), chip, field
      with label and error, section header, figure with label, dialog shell. Every page uses them; the `Card` in
      `components/plan/ui.tsx` is gone.
AC-3  A static test (`tests/design/tokens.test.ts`, in the style of `tests/db/scoping.test.ts`) fails when a
      component uses a pixel font size, `rounded-xl` or larger, a hand-written shadow, a Tailwind palette colour or
      a hex value. Exceptions are a short list in the test, each with its reason (chart internals, the theme colour
      in the root layout).
AC-4  The week review overlay fits a 390 × 844 screen without scrolling, with its action visible, and is no wider
      than 560 px on a desktop. What was cut is listed in the summary.
AC-5  Every page at 1440 and 390 px: no horizontal overflow, no console error, no text under 12 px, primary actions
      at least 44 px high on the phone. The plan page at 1440 px has no blank area beside the week strip.
AC-6  Text contrast is at least 4.5 : 1 for every text and background pair of the token set, in the light set and
      in the dark set of the marketing pages (computed in a test from the token values).
AC-7  Nothing but looks: no file under `lib/` or `app/api/` changes, apart from a class-name helper; UI texts stay
      as they are except in task 5. `npx tsc --noEmit`, `npm test` and `next build` are green.
AC-8  Before and after screenshots of every page at both widths exist for Livius; the screenshots in the README
      are the new ones.
</acceptance_criteria>
