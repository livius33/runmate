<objective>
## Goal
Clear the two advisories PR #7 left open on purpose, and keep dependencies from drifting again.

## Purpose
`drizzle-orm` ≥ 0.44 wraps every driver error in a message that contains the query and its parameters. About 30
handlers log `err.message`; after a plain update a database error would write health data and addresses into the
logs. `zod` 3 has no patched release; the exposure is a signed-in user sending an oversized collection.
</objective>

<context>
- Starts after PR #7 (lockfile) and the branches of 12-04 and 12-05 are on `main`: this plan edits the logging line
  of most route handlers and would conflict with both.
- Branch `fix/drizzle-update-safe-logging`, based on `main`.
</context>

<acceptance_criteria>
AC-1  `lib/server/log.ts` has one function that turns a caught error into a log text: the driver's message from
      the `cause` chain, never the text after "Failed query", never parameters. Tests with a wrapped error.
AC-2  No handler or lib module logs `err.message` or the error object of a database call directly; a static test in
      the style of `tests/db/scoping.test.ts` fails when one does.
AC-3  `drizzle-orm` ≥ 0.45.2; `drizzle-kit generate` reports no schema change; the three tests that read the
      driver message assert on `cause`.
AC-4  JSON bodies are read with a byte limit (256 KB unless a route needs more); `plan-overrides`,
      `runner/profile` and `feedback/week` reject oversized collections before validation.
AC-5  `npm audit --omit=dev` shows only the zod advisory, with a note in `SECURITY.md` on why it is not reachable
      beyond one's own request.
AC-6  `.github/dependabot.yml` (npm and GitHub Actions, weekly, minor and patch grouped); issue templates for bug
      and idea; `CODE_OF_CONDUCT.md`.
AC-7  `npx tsc --noEmit`, `npx vitest run` and `npm run build` are green.
</acceptance_criteria>

<tasks>
1. Log helper and its use at every site; static test.
2. `drizzle-orm` update; test changes.
3. Byte-limited JSON reader in the routes that accept collections (reuses the reader from 12-04).
4. Dependabot config, issue templates, code of conduct, `SECURITY.md` note.
</tasks>
